# Дополнительные замеры для второго раунда рецензирования (конфигурация D)

Замеры отвечают на замечания 1, 2, 3 и 5 рецензента 1: оптимизированный путь CPU на том же ноутбуке, что и GPU;
три независимых процесса для каждого замера; одна схема питания для всех прогонов и журнал частот GPU;
оптимизированный вариант GPU (повторное использование буферов устройства, ядро формирования с объединёнными
обращениями к памяти, табличное ядро распознавания, перебор размеров группы потоков); счётчики ядер Nsight Compute.

## Подготовка

1. Тот же ноутбук, что в первом раунде (ASUS ROG Strix SCAR 18), от сети, другие программы закрыты.
2. .NET 8 SDK и доступ к nuget.org (как в первый раз). Обновить репозиторий: `git pull`.
3. Текстовый файл тот же, что в первом раунде (русский текст в UTF-8), папка `data` репозитория.
4. Для счётчиков (шаг «ncu», по желанию): NVIDIA Nsight Compute (входит в CUDA Toolkit или ставится отдельно)
   и доступ к счётчикам: NVIDIA Control Panel → Desktop → Enable Developer Settings → Developer →
   Manage GPU Performance Counters → «Allow access to the GPU performance counters to all users»
   (или запуск командной строки от имени администратора).

## Запуск

В папке `measurement\laptop` репозитория:

```
run_revision2.cmd <текстовый файл> <папка data>
```

Всё вместе занимает около 2–2,5 ч. Можно по частям: последний аргумент — `env`, `breakeven`, `formation`,
`recovery`, `fullcycle`, `fullcycleseq`, `kernels`. Счётчики Nsight Compute — отдельной командой (около 5–10 мин):

```
run_revision2.cmd <текстовый файл> <папка data> ncu
```

Скрипт сам включает схему питания «Высокая производительность» на время замеров и возвращает прежнюю в конце,
а частоты, мощность и температуру дискретного GPU пишет каждые 0,5 с в `gpu_clocks_*.csv`. Если в фирменной
утилите ноутбука (Armoury Crate) есть свой режим, лучше выбрать «Performance» или «Turbo» и не менять его до конца.

## Результат

Папка `results_revision2` рядом со скриптом. Её нужно заархивировать и прислать целиком.
Если какой-то шаг завершился с ошибкой, в папке будет файл `*.console.log` или `*.err` с текстом ошибки — его тоже прислать.
