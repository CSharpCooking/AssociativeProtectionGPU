# Замеры для доработки на ноутбуке с GPU

Код дополнительных замеров на компьютере с GPU: на ноутбуке, где мерились GPU в статье (конфигурация A: Intel Core
i5-13420H, Intel UHD Graphics, NVIDIA GeForce RTX 4050 Laptop GPU), или на другом — например, на ноутбуке
конфигурации C (Intel Core i5-9300H, NVIDIA GeForce RTX 2060). В статье эти замеры пока не используются; разд. 8.7
перечисляет, что они добавят.

Собрать код можно двумя способами:

* **Внутри проекта бенчмарков ВКР**, где уже есть библиотека и пакеты: скопировать туда шесть файлов `.cs` из этой
  папки (подробно ниже).
* **Самостоятельно** (`standalone/AssocRevision.csproj`) — если проекта ВКР на компьютере нет. Проект собирает
  листинг библиотеки из ВКР (`library/CpuGpuStego.cs`), совместимый `BitVector` (`measurement/AssocMeasure/Thesis/`)
  и файлы этой папки; пакеты ILGPU 1.5.3, ILGPU.Algorithms 1.5.3 и BenchmarkDotNet 0.15.8 скачиваются из NuGet при
  сборке. Нужны .NET 8 SDK и репозиторий целиком (с той же структурой папок).

Дискретный GPU выбирается через `AcceleratorSelector.Create(ExecutionMode.NvidiaDiscreteGpu)`, то есть через CUDA,
встроенный — через `AcceleratorSelector.Create(ExecutionMode.IntegratedGpu)`, через OpenCL. Если какого-то устройства
нет (например, встроенная графика отключена), его варианты завершатся ошибкой, остальные пройдут.

Код компилировался только с заглушками ILGPU и BenchmarkDotNet: там, где писался набор, пакеты скачать нельзя. На
эмуляции ILGPU все варианты всех классов восстановили вход побайтно без утечек буферов, в том числе в самостоятельной
сборке с листингом библиотеки. С настоящими пакетами код не собирался, поэтому может понадобиться мелкая правка.

## Подготовка

* **Проект ВКР.** Скопировать в проект бенчмарков ВКР (тот, где `StegoBenchmarks`) шесть файлов `.cs` этой папки (без
  папки `standalone`). В `Program.Main` первой строкой вставить
  `if (args.Length > 0 && args[0].StartsWith("rev")) { RevEntry.Run(args); return; }`
  (если `Main` возвращает `int` — `return RevEntry.Run(args);`). Положить `run_revision.cmd` в папку проекта.
* **Самостоятельно.** Ничего готовить не нужно: `run_revision.cmd` остаётся в этой папке и сам собирает
  `standalone/AssocRevision.csproj`, если рядом с ним нет другого `.csproj`. Нужен .NET 8 SDK.
* Ноутбук — от сети, схема питания «Высокая производительность», остальные программы закрыты, обновления Windows
  не идут. Запускать из консоли (cmd или PowerShell), не из Visual Studio: тогда к процессу не подключён отладчик.

## Запуск

```
run_revision.cmd <файл романа.txt> <репозиторий>\data
```

Первый аргумент — текстовый файл романа, из которого делались входы статьи (615 049 байт); второй — папка `data`
репозитория (нужны `uniform_10MB.bin`, `ff_10MB.bin`, `zero_10MB.bin`, `ru_10MB.bin`). Из папки `measurement\laptop`
это, например, `run_revision.cmd D:\book.txt ..\..\data`. Третьим аргументом можно запустить одну группу: `env`,
`breakeven`, `fullcycle`, `formation`, `chunksize`, `recovery`, `recognition`, `kernels`. Для проверки, что всё
собралось и работает, удобно начать с `formation` (несколько минут).

| Группа | Что измеряет | Время на A | Для замечаний |
|---|---|---|---|
| env | Версии .NET, ILGPU, BenchmarkDotNet, ОС, драйверов GPU, схема питания, питание от сети | < 1 мин | Р2-4, Р3-5 |
| breakeven | Полный цикл на 1, 10, 20, 30, 40, 50, 60, 75, 100 КБ: CPU-seq и исходные GPU-классы, 3 процесса на вариант | 15–25 мин | Р1-5.1, Р2-4, Р2-5, Р3-5 |
| fullcycle | Полный цикл 100 МБ: многопоточный CPU (порционный генератор или функция заполнителя GPU, перебор или таблица) и оба GPU | ≈ 8 мин | Р1-2.5, Р2-2, Р3-2 |
| formation | Формирование 10 МБ: эталон, последовательно с порционным генератором и с функцией GPU, то же на всех потоках, оба GPU | ≈ 3 мин | Р2-3, Р3-2 |
| chunksize | Полный цикл 100 МБ с порциями 256, 512, 1024, 2048 КБ в одной сборке и одном прогоне; исходные классы (512 КБ); CPU-seq — контроль состояния машины | ≈ 17 мин | Р1-2.1, Р2-8, Р3-3 |
| recovery | Восстановление 10 МБ: перебор и таблица на CPU, исходное и новое ядро перебора, табличное и безветвлённое ядра на обоих GPU | ≈ 5 мин | Р1-1.3, Р1-4, Р3-4 |
| recognition | Восстановление 10 МБ входов uniform, ff, zero, ru из `data/`: CPU-seq, таблица на CPU, три ядра на обоих GPU | ≈ 13 мин | Р1-4, Р1-5.2, Р3-4 |
| kernels | Время самих ядер при данных в памяти устройства, копирований на устройство и обратно, записи и чтения файла | 3–5 мин | Р1-2.3, Р1-4, Р3-4 |

Весь прогон — около 1–1,5 ч на A и около 1,5–2 ч на C (процессор медленнее, а эталонная реализация на CPU занимает
большую часть времени). Результаты — в папке `results_revision` рядом со скриптом; её нужно прислать архивом zip. В
подпапке каждой группы BenchmarkDotNet пишет отчёты и лог со временем каждой прогревочной и измеряемой итерации.

## Профиль ядер (по желанию)

Нужен Nsight Compute (входит в CUDA Toolkit) и доступ к счётчикам производительности GPU: в панели управления NVIDIA
включить режим разработчика и разрешить доступ к счётчикам для всех пользователей либо запускать консоль от
администратора. Затем в папке собранного проекта (для самостоятельной сборки — `standalone`):

```
ncu --target-processes all --set full --export rev_kernels_dgpu dotnet run -c Release --no-build -- rev-kernels <репозиторий>\data 1 dGPU
ncu --import rev_kernels_dgpu.ncu-rep --page details --csv > rev_kernels_dgpu.csv
```

Прислать оба файла.

## Ещё одно

Если на ноутбуке A найдётся папка `BenchmarkDotNet.Artifacts` исходных прогонов ВКР (по умолчанию —
`<проект>\bin\Release\net7.0\BenchmarkDotNet.Artifacts` или папка проекта), её тоже прислать: в логах исходных
прогонов есть число прогревочных итераций, которого нет в отчётах.
