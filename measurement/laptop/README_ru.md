# Замеры для доработки на конфигурации A

Код дополнительных замеров на ноутбуке, где измерялись GPU (конфигурация A: Intel Core i5-13420H, Intel UHD Graphics
через OpenCL, NVIDIA GeForce RTX 4050 Laptop GPU через CUDA). В статье эти замеры пока не используются; разд. 8.7
перечисляет, что они добавят.

Файлы добавляются в проект бенчмарков ВКР: там уже есть библиотека и пакеты ILGPU 1.5.3 и BenchmarkDotNet 0.15.8.
Классы компилировались только с заглушками ILGPU и BenchmarkDotNet, потому что там, где писался набор, пакеты
скачать нельзя. На эмуляции ILGPU все варианты всех классов восстановили вход побайтно и не оставили неосвобождённых
буферов. С настоящими пакетами набор не собирался, поэтому на ноутбуке может понадобиться мелкая правка.

## Подготовка

1. Скопировать в проект бенчмарков ВКР (тот, где `StegoBenchmarks`) шесть файлов `.cs` из этой папки.
2. В `Program.Main` первой строкой вставить
   `if (args.Length > 0 && args[0].StartsWith("rev")) { RevEntry.Run(args); return; }`
   (если `Main` возвращает `int` — `return RevEntry.Run(args);`).
3. Положить `run_revision.cmd` в папку проекта (рядом с `.csproj`).
4. Ноутбук — от сети, схема питания «Высокая производительность» (или максимальная производительность в настройках
   питания Windows 11), остальные программы закрыты, обновления Windows не идут.
5. Запускать из консоли (cmd или PowerShell), не из Visual Studio: тогда к процессу не подключён отладчик.

## Запуск

```
run_revision.cmd <файл романа.txt> <репозиторий>\data
```

Первый аргумент — текстовый файл романа, из которого делались входы статьи; второй — папка `data` этого репозитория
(нужны файлы `uniform_10MB.bin`, `ff_10MB.bin`, `zero_10MB.bin`, `ru_10MB.bin`). Третьим аргументом можно запустить
одну группу: `env`, `breakeven`, `fullcycle`, `formation`, `chunksize`, `recovery`, `recognition`, `kernels`. Для
проверки, что всё собралось и работает, удобно начать с `formation` (около 3 мин).

| Группа | Что измеряет | Время | Для замечаний |
|---|---|---|---|
| env | Версии .NET, ILGPU, BenchmarkDotNet, ОС, драйверов GPU, схема питания, питание от сети | < 1 мин | Р2-4, Р3-5 |
| breakeven | Полный цикл на 1, 10, 20, 30, 40, 50, 60, 75, 100 КБ: CPU-seq и исходные GPU-классы, 3 процесса на вариант | 15–25 мин | Р1-5.1, Р2-4, Р2-5, Р3-5 |
| fullcycle | Полный цикл 100 МБ: многопоточный CPU (порционный генератор или функция заполнителя GPU, перебор или таблица) и оба GPU | ≈ 8 мин | Р1-2.5, Р2-2, Р3-2 |
| formation | Формирование 10 МБ: эталон, последовательно с порционным генератором и с функцией GPU, то же на всех потоках, оба GPU | ≈ 3 мин | Р2-3, Р3-2 |
| chunksize | Полный цикл 100 МБ с порциями 256, 512, 1024, 2048 КБ в одной сборке и одном прогоне; исходные классы (512 КБ); CPU-seq — контроль состояния машины | ≈ 17 мин | Р1-2.1, Р2-8, Р3-3 |
| recovery | Восстановление 10 МБ: перебор и таблица на CPU, исходное и новое ядро перебора, табличное и безветвлённое ядра на обоих GPU | ≈ 5 мин | Р1-1.3, Р1-4, Р3-4 |
| recognition | Восстановление 10 МБ входов uniform, ff, zero, ru из `data/`: CPU-seq, таблица на CPU, три ядра на обоих GPU | ≈ 13 мин | Р1-4, Р1-5.2, Р3-4 |
| kernels | Время самих ядер при данных в памяти устройства, копирований на устройство и обратно, записи и чтения файла | 3–5 мин | Р1-2.3, Р1-4, Р3-4 |

Весь прогон — около 1–1,5 ч. Результаты — в папке `results_A_revision` рядом со скриптом; её нужно прислать архивом
zip. В подпапке каждой группы BenchmarkDotNet пишет отчёты и лог со временем каждой прогревочной и измеряемой итерации.

## Профиль ядер (по желанию)

Нужен Nsight Compute (входит в CUDA Toolkit) и доступ к счётчикам производительности GPU: в панели управления NVIDIA
включить режим разработчика и разрешить доступ к счётчикам для всех пользователей либо запускать консоль от
администратора. Затем в папке проекта:

```
ncu --target-processes all --set full --export rev_kernels_dgpu dotnet run -c Release --no-build -- rev-kernels <репозиторий>\data 1 dGPU
ncu --import rev_kernels_dgpu.ncu-rep --page details --csv > rev_kernels_dgpu.csv
```

Прислать оба файла.

## Ещё одно

Если на ноутбуке найдётся папка `BenchmarkDotNet.Artifacts` исходных прогонов ВКР (по умолчанию —
`<проект>\bin\Release\net7.0\BenchmarkDotNet.Artifacts` или папка проекта), её тоже прислать: в логах исходных
прогонов есть число прогревочных итераций, которого нет в отчётах.
